# handoff.md

> Handoff 文档的职责、场景与模板。
> 与 `workflow.md` §2.3 配套：workflow 规定"何时写、放哪里"，本件规定"写什么、跨哪些边界"。

## 1. Handoff 是什么

一句话：**把一件事的上下文完整交给下一个执行者**的文档。

它不限于"项目内任务交付"。凡上下文需要**跨边界**传递——换 Agent、换工具、换项目、换人/小组——都用 handoff，保证接手者不盲启动。

## 2. 五种场景（按"跨什么边界"分）

| 场景 | 跨什么 | 典型例子 | 默认启用 |
|---|---|---|:---:|
| **A · 项目内任务交付** | 任务 → 任务 | PRD 批准后拆给实施 | ✅ |
| **B · 跨 Agent 交接** | Agent → Agent | Claude 写完前端交另一个 Agent 续后端 | 按需 |
| **C · 跨工具迁移** | 工具 → 工具 | 从 Codex 迁到 Cursor / Aider | 按需 |
| **D · 跨项目资产** | 项目 → 项目 | 把本仓 `glossary/` 复用到新仓 | 按需 |
| **E · 跨小组协作** | 人/组 → 人/组 | 前端组交后端组联调 | 按需 |

> 本仓启用哪些场景，在 `project-init.md` §2.1 与用户确认（见 T4 落地）。未确认时默认只 A。

## 3. 统一放哪里

**所有场景都放** `docs/output/handoff/{theme}/{task}.md`——**不按场景分目录**。场景由文档内的「给下一个执行者」段区分，避免目录碎片化。

```text
docs/output/handoff/
├── {theme}/{task}.md       # 单个 handoff
└── archive/{theme}/        # 过期归档（见 archive.md）
```

## 4. 文档模板

### 4.1 通用骨架（所有场景必填）

```markdown
# {task} · Handoff

## Status
draft | awaiting-review | approved | archived

## 背景
为什么做、关联的 PRD / Issue / 上游 handoff。

## 改动点
- 文件 / 模块清单，每项一句话说改了什么。

## 验收步骤
1. 可复现的检验步骤（启动命令、点击路径、预期结果）。

## 回滚
- revert 哪几个 commit hash / 配置开关 / 数据回退方式。

## 已知风险与未决项
- 遗留问题、假设、待确认项。
```

### 4.2 跨边界额外段（场景 B/C/D/E 追加）

在通用骨架末尾加：

```markdown
## 给下一个执行者
- 目标执行者：{Claude / Cursor / 后端组 / 新仓 Agent / …}
- 必读上下文：{CONTEXT.md · docs/glossary/frontend-ui.md · 某文件:行}
- 工具 / 环境差异：{如"Cursor 不认 matt-pocock skills"、"目标仓无 /api 代理"}
- 资产清单（D 专用）：{要迁的文件 + 目标仓落位}
- 验收方：{谁拍板完成}
```

场景 A 不需要此段；B/C/D/E 必填，**漏「必读上下文」等于让接手者盲启动**。

## 5. 写作要点

- **可复现优先**：验收步骤必须能被接手者照着跑通，不写"大概没问题"。
- **列改动，不列思路**：改了哪些文件、行为变了几行，而不是设计推导。
- **标未决项**：没做的、假设的、待确认的，单列一节，不藏进正文。
- **跨工具时标注差异**：源工具认得、目标工具不认得的约定（skill、路径别名、MCP）必须写明。

## 6. 门禁

- 无 handoff → 不开工（与 `workflow.md` §3 一致）。
- 跨边界 handoff 必须有「给下一个执行者 · 必读上下文」。
- Review 通过后移入 `archive/`（见 `archive.md`）。
